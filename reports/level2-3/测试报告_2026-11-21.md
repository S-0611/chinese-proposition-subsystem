# 二、三级题库导入 + 接口测试报告（2026-11-21）

## 结论

- 接口层「按等级查询 + 防串题」测试 **20/20 全部通过**：`GET /api/questions?level=2`、`level=3` 只返回本级题目，不返回一级题目，也不互相串题。
- 但**正式题库导入跑不通**，卡在数据侧两处问题，需谷财佾确认/补齐后才能做真正的二、三级入库。

## 阻塞项

1. `banks/level2/final.json`、`banks/level3/final.json` 尚未交付，`python backend/import_bank.py --level 2/3` 直接报「题库文件不存在」。本次测试用各 6 道占位冒烟题走真实导入链路，仅验证接口过滤，不代表正式题库内容。
2. `data/levels/level2.json`—`level9.json` 与 `level1.json` 模板不一致，`scripts/pipeline.py` 直接 `KeyError: 'constraints'`，`/api/pipeline/publish` 也会因统计阶段同样报错而无法发布：
   - 缺 `constraints`（字数上下限、是否允许字母数字）
   - 缺 `thresholds`（覆盖率/词频阈值）
   - `chars` 是纯数组（模板要求 `{"all": [...], "core": [...]}`）
   - `grammar` 是 `{"new_count": 81, "total_count": 129}` 计数对象（模板要求 `[{"id","name","pattern","desc"}]`）
   - 7—9 级没有 `chars` 列表，只有计数
3. `data/levels/level3.json` 原文件末尾多了 Markdown 代码围栏 ```，JSON 解析失败（Extra data: line 62）。**本次已修复**，修复后 2—9 级 JSON 全部可解析。

## 测试方法

- 测试脚本：`backend/test_level23.py`（独立临时库 + 独立端口 8019，不触碰 `backend/bank.db`）。
- 一级用正式库 `banks/level1/final.json` 共 256 题；二、三级各导入 6 道占位冒烟题。
- 因正式 publish 依赖统计达标与人工复核，占位题在测试库中直接置为 `published`，仅用于验证抽题接口过滤。

## 测试结果（20/20）

- `level=2`：200、共 6 题、全部 `level==2`、无一级题目
- `level=3`：200、共 6 题、全部 `level==3`、无一级题目、无二级题目
- `level=1`：仍为 256 题，未混入二、三级
- 不带 level：共 268 题，只含 1/2/3 级
- `/api/levels`：二、三级 `available`（各 6 题），四级仍 `pending`
- `random?level=2`、`random?level=3`：均 200，且只返回本级题目

证据文件：`reports/level2-3/api_level23_test_20261121_155238.txt`

```bash
python backend/test_level23.py

```

## 建议

- 谷财佾按 `level1.json` 模板补齐 `constraints`、`thresholds`、`chars.all/core`、带 `id/pattern` 的语法点列表；7—9 级需先确认是否有分级字表，无依据就标「待标准确认」，不要用计数冒充。
- 正式 `banks/level2|3/final.json` 交付后，跑 `python scripts/pipeline.py --level N` → `python backend/import_bank.py --level N` → `python backend/test_level23.py --skip-server` 复核。
- 前端状态看板可先接 `/api/levels`，当前二、三级会在占位导入后显示 `available`，正式库落地前不要对外宣称题库完成。
