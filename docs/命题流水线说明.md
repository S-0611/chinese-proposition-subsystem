# 分级跟读命题工作流

## 一、这套工作流解决什么问题

给发音评测系统出跟读题，不能想到什么写什么。一级的学生只认识 300 个字，题目里出现一个超纲字，这道题就作废；同时题库作为一个整体，还要保证这 300 个字都练到、41 个语法点都出现，否则题库覆盖不全。

所以命题分成两个层面：

1. 单题合格：每个字都在本等级字表内，句长在范围内，声明的语法点真实出现在句子里。
2. 题库达标：字覆盖率、语法覆盖率、每个字和每个语法点的出现次数都达到该等级的阈值。

单题靠人肉眼逐字核对又慢又容易漏，题库达标更没法靠感觉判断。本工作流用三个脚本把两件事都变成程序判定：先出题，再校验，再统计，统计不达标就按缺口清单补题，循环到达标为止。

## 二、目录结构

```
命题/
  skill.md                  本文档
  README.md                 快速上手
  data/levels/level1.json   等级数据：字表、核心字、语法点、约束、阈值
  scripts/
    build_level1.py         生成 level1.json（改字表后重跑）
    validate.py             单独跑校验
    stats.py                单独跑统计
    pipeline.py             一键跑校验加统计；合并多轮题库
  banks/level1/             题库：round1.json、round2_add.json、round3_add.json、final.json
  reports/level1/           每一轮的校验报告、统计报告、调整计划
```

## 三、等级数据文件

每个等级一个 JSON（data/levels/levelN.json），四个部分：

| 字段 | 内容 | 一级的取值 |
| --- | --- | --- |
| chars.all | 该等级允许使用的全部汉字 | 300 字，参照《国际中文教育中文水平等级标准》一级字表整理 |
| chars.core | 高频核心字，复现要求更高 | 128 字，要求每字至少出现 3 次 |
| grammar | 语法点列表，每点带 id、名称、检测正则、说明 | 41 个点，从"是"字句到双宾句 |
| constraints | 句长 3 到 12 字、禁用字母数字、题量目标区间 | 题量 110 到 280 题 |
| thresholds | 达标阈值 | 字覆盖率不低于 90%，语法覆盖率 100%，核心字每字至少 3 次，语法点每点至少 2 次 |

语法点的 pattern 是宽松的正则，用于程序初筛；正则测不出的细节仍需人工抽检，这一点在第七节说明。修改字表或语法点后，重跑 `python scripts/build_level1.py` 重新生成等级文件。

## 四、出题规则（第一步）

出题文本的来源可由用户选择：由大模型按等级字表和语法点生成，或者检索互联网上的现成文本（如分级读物、教材例句）。不管哪种来源，产出的句子都要按下面的格式整理，并同样通过第二步校验；检索来的文本几乎不会正好落在字表内，通常需要按字表改写后再入库。

每道题是一个 JSON 对象，写入 banks/levelN/roundK.json 或 roundK_add.json：

```json
{"id": "L1-001", "level": 1, "round": 1,
 "text": "我姓王，你姓什么？",
 "pinyin": "wǒ xìng Wáng, nǐ xìng shénme?",
 "grammar": ["G1-04"]}
```

出题时必须遵守：

1. 只用字表内的字，一个都不能超。拿不准的字宁可换说法。
2. 汉字数量在 min_chars 到 max_chars 之间（一级是 3 到 12 字，标点不计）。
3. 不用阿拉伯数字和拉丁字母，数字写汉字（七点、十块钱）。
4. 每题声明至少一个语法点，且声明的语法点要真实体现在句子里，校验会用正则核对。
5. 每题配拼音，便于人工审读和后续接语音合成。
6. 句子要口语化、场景真实（打招呼、买东西、问路、聊家人），适合朗读。
7. id 全库唯一，建议按 L等级-序号 编号；新增题用新的 round 字段标记轮次。

补题轮（第二轮起）按第三步产出的调整计划写题：每个缺口字安排进句子，每题打包 2 到 4 个缺口字；缺口语法点每点至少两题，尽量和缺口字合并进同一题；低频核心字按差额补次数。

## 五、校验（第二步）

```
python scripts/pipeline.py --level 1 --bank banks/level1/final.json --tag final
```

校验逐题检查：字是否都在字表内、字数是否越界、有没有字母数字、声明的语法点 id 是否属于本等级、声明的语法点正则是否命中句子、id 和文本是否重复。不合格题会连同原因写入 reports/level1/validate_标签.md。

处理方式只有两种：改句子，或者删掉。改完后重跑，直到"不合格 0 题"才进入统计。

常见校验错误对照：

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| 超出本等级字表：某字 | 用了超纲字 | 换同义的说法，或整题重写 |
| 字数超出范围 | 句子太长或太短 | 拆句或扩句 |
| 语法点与文本不符 | 声明了但句子里没有，或正则没覆盖这种句式 | 先核对句子是否真用了该语法点；确实是正则漏了就去修等级文件里的 pattern，不能为了过校验乱改句子 |
| 重复 id 或重复文本 | 编号或句子撞车 | 重新编号或改写 |

## 六、统计与调整（第三、四步）

校验通过后，同一个命令会接着统计并给出结论：

- 字覆盖：合格题里出现过的字占字表的比例，列出没覆盖的字。
- 字频：每个字出现多少次，核心字不足 threshold 的单独列出。
- 语法覆盖：41 个语法点各出现多少次，低于 grammar_freq_min 的单独列出。
- 结论：达标（退出码 0）或未达标（退出码 2），同时写出调整计划 reports/level1/adjust_plan_标签.json。

调整计划包含四类缺口和补题建议：

| 缺口类型 | 含义 | 怎么补 |
| --- | --- | --- |
| new_chars | 出现 0 次的字 | 每题打包 2 到 4 个缺口字造新句 |
| boost_chars | 核心字次数不足 | 按 need 差额安排进新句 |
| new_grammar | 0 次的语法点 | 每点至少 2 题 |
| boost_grammar | 次数不足的语法点 | 补足到 grammar_freq_min |

补题写入 roundK_add.json，合并后作为新一轮题库复跑：

```
python scripts/pipeline.py banks/level1/round1.json banks/level1/round2_add.json --out banks/level1/round2.json
python scripts/pipeline.py --level 1 --bank banks/level1/round2.json --tag v2
```

循环出题、校验、统计、调整，直到结论为达标。工作流的退出条件只有一个：统计结论达标。如果某个字实在造不出符合等级的句子，不要硬凑，回等级文件把它换成可用的同级字（在 build 脚本的字表分组里改，保持总数不变），并重新走一遍流程。

## 七、人工抽检

程序判定有两处天然局限，达标后仍需人工过一遍：

1. 语法正则是宽松匹配。比如"对"字既可能是介词"对"也可能是"对不起"里的字，正则会把后者也算进介词用法；"住在学校"里的"学"会被当成动词命中"在加处所加动词"。方向上不漏，但个别计数偏宽。
2. 声明的语法点只验证正则命中，句子是否真符合该语法点的教学定义（比如双宾句的宾语次序），需要教师抽检。

建议每轮按 10% 抽检，重点看声明语法点多的题和正则匹配宽泛的题。抽检发现的问题按第四步处理：改题或改规则，复跑。

## 八、一级实践记录（本工作流的完整示例）

一级题库三轮达标，全程记录在 reports/level1/：

| 轮次 | 题数 | 字覆盖 | 校验不合格 | 说明 |
| --- | --- | --- | --- | --- |
| v1（round1） | 123 | 80.3%（241 字） | 4 题 | 首轮自由命题，语法全命中但字缺口 59 个，64 个核心字复现不足 |
| v2（round1 加 round2_add） | 251 | 99.7%（299 字） | 9 题 | 按缺口清单补 128 题；校验器同时抓出 6 处句子错误和 3 处规则正则漏洞，分别修正 |
| final（加 round3_add） | 256 | 100%（300 字） | 0 题 | 补 5 题收尾，300 字全部覆盖，核心字每字至少 3 次，41 个语法点每点至少 2 次 |

三轮共修正的问题类型：超纲字（晴、作、首、这、那）、时间词没有放句首、语法点声明与句子不符、正则的边界（"去买"这类动词直连、"一万个"的大数字）。这些正是人工命题最容易犯的错，都可以靠校验器兜住。

## 九、扩展到其他等级

1. 复制 scripts/build_level1.py 改名 build_level2.py，替换 CHARS_GROUPS 为该等级字表（累计制：二级 600 字含一级 300 字）、GRAMMAR 为该等级语法点，调整 constraints 和 thresholds（二级句长建议 4 到 16 字，覆盖率阈值不变）。
2. 跑 `python scripts/build_level2.py` 生成等级文件。
3. 按本文档第四步到第六步出题、校验、统计、调整，流程完全相同。
4. 等级与演示系统的对应：一级到三级对应系统的 beginner（初级字词），四级对应 inter（中级句子），五级以上对应 advanced（高级语篇）。跟读题题库按等级标准的一到九级建，导入演示系统时按此映射归入三个难度层。

## 十、扩展方向

- 声韵调覆盖：跟读题最终服务于发音评测，进阶做法是在统计脚本里加一步，按拼音统计声母、韵母、声调的组合覆盖，让题库不只覆盖字，还覆盖音节。
- 题型扩展：dialogue（两句对话）和 passage（短文）类型，校验逻辑需按行拆开检查。
- 出题来源与自动化：第一步的出题由人、大模型生成或互联网检索完成（见第四节），题库规模大时可以把调整计划直接作为生成提示词，批量产题后仍走同一套校验统计。
