## 二、逐字段解释

### A. 顶层元信息

**1. `level`** — 等级序号，整数 1–9。
- 当前值：`1`
- 状态：**✅**
- 依据：标准「三等九级」体系（第 2 章术语 2.3，书内 1 页）；序号与总表一致。
- 2–9 级取值：2、3、4、5、6、7、8、9，无歧义。

**2. `name`** — 等级中文全称。
- 当前值：`"一级（初等一级）"`
- 状态：**◐**
- 依据：标准称「一级」，「初等」是三档之一（3.1 初等）。
- 待定：2–9 级是否统一为「二级（初等二级）」…「九级（高等九级）」？现有写法把「等」和「级」拼在一起（初等一级），标准原文只有「初等」「一级」两个概念，**拼接方式是项目自定**，需你确认命名规则。

**3. `tier`** — 阶段枚举，供程序分档。
- 当前值：`"beginner"`
- 状态：**◐**
- 依据：三等九级 → 初等（1–3）、中等（4–6）、高等（7–9）已确认。
- 待定：枚举字符串只有 `beginner` 一个实例，`intermediate` / `advanced` 未被任何文件验证，**属于推断**。

**4. `source_note`** — 来源说明文本。
- 当前值：「字表与语法点参照…一级大纲口径整理，共 300 字；如需与官方逐字对齐，修改 build_level1.py 中 CHARS_GROUPS 后重跑即可。」
- 状态：**✖ 需重写**
- 问题：这句话等于自认「非官方逐字」。实际核查结果是：汉字数量与 5.1 表一致（300），但**排序与分组明显被重排**（PDF 表按拼音字母序：爱→八→爸；json 按主题分组：一→二→三…），因此不能称「与大纲一致」；同时 `chars.core` 128 字与 `grammar` 42 条都无官方对应。说明文字必须如实写清三件事：哪些来自 5.x 表、哪些是项目筛选、哪些是二次改写。

### B. 工程约束 `constraints`

**5. `constraints.min_chars` = 3；6. `max_chars` = 12** — 词条长度上下限（太短无法成题，太长不利判分）。
- 状态：**▢**
- 依据：标准中**没有**任何关于词条长度的规定；这是题库工程参数，只能由业务确认。
- 建议：2–9 级是否沿用 3–12？高级词汇（如「社会主义」「通货膨胀」）4 字以内没问题，但成语、惯用语会顶到 8–12 字，需确认是否放宽。

**7. `allow_ascii` = false；8. `allow_digits` = false** — 词条是否允许出现拉丁字母、阿拉伯数字。
- 状态：**▢**
- 依据：标准词汇表里确实存在带字母/数字的条目（如「AA 制」「K 歌」一类在高等词汇中常见），一级不会出现。若要覆盖 7–9 级，**这两项很可能需要翻成 true**，属于必须业务决策的点。

**9. `bank_target_items` = [110, 280]** — 每级目标题量区间（下限 110、上限 280）。
- 状态：**▢**
- 依据：纯项目指标。注意取值与「语法点 48 条 × 每点 ≥2 次」存在耦合，改动需同步看 `grammar_freq_min`。

### C. 校验阈值 `thresholds`

| 字段 | 当前值 | 含义（按命名与取值推断） | 状态 |
|---|---|---|---|
| `char_coverage_min` | 0.9 | 题库需覆盖 `chars.all` 的比例下限（≥90%） | ▢ |
| `char_freq_min` | 1 | 每个汉字在题库中至少出现 1 次 | ▢ |
| `core_char_freq_min` | 3 | 每个核心字至少出现 3 次 | ▢ |
| `grammar_coverage_min` | 1.0 | 每个语法点必须 100% 覆盖 | ▢ |
| `grammar_freq_min` | 2 | 每个语法点至少对应 2 道题 | ▢ |

- 状态统一为 **▢**：这五个是**评分/验收口径**，标准里完全没有，只能由产品与教研确认。
- 逻辑一致性提醒：一级 48 条语法 × 2 = 96 题，落在 `[110,280]` 内合理；但若 2–9 级仍用 2 次，二级 81 条 × 2 = 162，会直接顶到区间中段，**高级（148 条）则需 296 题，超出 280 上限**。这条必须改，否则校验必失败。
- 依赖关系：`core_char_freq_min` 的取值依赖 `chars.core` 的定义——核心字若按书写表取 200 个，则 200×3=600 次，与题量匹配；若按 128 个自定义字取，口径就对不上。

### D. 语言数据

**15. `chars.all`** — 本级要求掌握的汉字全集。
- 当前值：300 个（一级）
- 状态：**◐ 部分确认**
- 依据：5.1 一级汉字表，**书内 15–16 页 / PDF 21–22 页**，编号 1–300（1 爱 … 300 做）。数量一致。
- 疑点（抽检发现，需人工逐字确认）：
  - PDF 表按**拼音字母序**排列，json 按**主题分组**排列 → 说明 json 是重排而非照录；
  - json 中「春」「夏」「冬」「每」等字，在 5.1 表编号范围内未见对应位置；
  - 相反，5.1 表中的「爱」「八」「爸」等首段字在 json 中靠后或另置。
- 结论：**可以用，但必须标注「按主题重排，非原表序」**；若要「逐字对齐官方」，应直接按表内编号录入。

**16. `chars.core`** — 本级核心字（高频、需重点考查的字）。
- 当前值：128 个（的、我、你、他… 一、二、两…）
- 状态：**✖ 无官方依据**
- 依据：**标准全文没有「核心字」这张表**。最接近的官方字表是 5.8 手写汉字表（5.8.1 初等 300 / 5.8.2 中等 400 / 5.8.3 高等 500，书内 30–36 页），而「本级要掌握多少个」写在能力条文里：一级 100 个、二级 200、三级 300、四级 100（中等表）、五级 250、六级 400、高等累计 1200（新增 500）。
- 冲突点：一级按条文应为 **100 字**，文件里是 **128 字**，两者不匹配，且没有任何注释说明筛选规则。
- 处理建议：二选一——(A) 改为 5.8.1 表前 100 字，`source_note` 引 3.1.1；(B) 保留 128 字，但必须写明筛选规则（字频阈值、功能字优先等）与脚本，并在文档中标「项目自定义」。

**17. `grammar[].id`** — 语法点编号，格式 `G{级}-{两位序号}`（如 `G1-01`）。
- 状态：**✅**
- 依据：编号是项目内部规则，与标准【一—01…48】编号**不同体系**，但足以唯一定位，不影响溯源。建议在 `source_note` 里给出「G 编号 ↔ 标准【一—NN】」的映射表。

**18. `grammar[].name`** — 语法点名称。
- 状态：**◐ 部分确认**
- 依据：A.1 一级语法点，**书内 170–179 页 / PDF 176–185 页**，共 48 条。
- 实测：json 42 条中，约 23 条能直接对上 A.1（是字句↔【一36】、有字句↔【一37】、吗提问↔【一45】、正反问↔【一48】、祈使↔【一34】、感叹↔【一35】、程度副词↔【一09】、否定副词↔【一14】、关联副词↔【一13】、范围副词↔【一10】、数量短语↔【一23】…）。
- 明细见第四节「42 vs 48 差异清单」。

**19. `grammar[].pattern`** — 用于题库匹配的正则表达式（如 `太[^，。？！]{1,6}了`）。
- 状态：**▢ 纯自定义**
- 依据：标准只给语法点名称、结构说明与例句，**不给任何机器可读模式**。正则的好坏只能靠抽样跑题库验证。
- 风险点：`pattern` 过宽（如 `"就"`、`"还"`、`"的"`）会大量误命中；过窄（如 `^(今天|明天|昨天…)` 带锚点）在句中永远匹配不到。建议补一列 `match_scope`（句首/句内）或改为「例句集匹配」。

**20. `grammar[].desc`** — 一句话说明 + 例句。
- 状态：**◐ 未逐条比对**
- 依据：A.1 每条语法点下都带 3–5 个例句（如【一36】"是"字句），可作为 desc 的合法来源。
- 问题：现有 desc 的例句（「我是学生。」「我有一个哥哥。」）**无法确认是否为原文例句**，部分是改写或自造。若要求「与标准一致」，需逐条替换为标准原句；若允许自造，应在 `source_note` 声明「例句为自编示例，非原文」。
