# 命题子系统后端接口说明（初稿）

> 成员B（李勃霖）· 2026-11-18 · 版本 v0.2.0
> 范围：题库导入、查询、校验、统计、状态管理、发布、按等级抽题、按覆盖程度抽题。

## 1. 启动方式

```powershell
# 项目根目录（chinese-proposition-subsystem）
python backend/init_db.py --reset        # 首次：建库（重置可选）
python backend/import_bank.py            # 导入 banks/level1/final.json（256 题）
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

- Swagger 文档（可在线调试）：http://127.0.0.1:8000/docs
- 数据库文件：`backend/bank.db`（SQLite，可用上述脚本重建；已被 .gitignore 忽略）
- 依赖：Python 3.11、fastapi、uvicorn、pypinyin（仅导入脚本用）

## 2. 统一题目字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 题目唯一编号，如 L1-001 |
| level | int | 等级 |
| text | string | 跟读文本（保留标点） |
| tokens | array | `[{"c":"我","py":"wǒ"}]` 汉字与拼音逐字对应 |
| grammar | array | 语法点编号，如 ["G1-04"] |
| status | string | draft / validated / rejected / ready / published |
| rec_count | int | 有效录音数（成功上传并保存的录音） |
| last_selected_at | string/null | 最近抽取时间（ISO 8601，UTC+8），未抽过为 null |

## 3. 接口清单

### 查询

1. `GET /api/questions` 全部题目；参数 `?level=1`（按等级）、`?status=published`（按状态）。返回 `{"total": n, "items": [...]}`；等级无题时 `total=0`。
2. `GET /api/questions/{id}` 单题；不存在返回 404 `{"detail": "题目不存在：xxx"}`。

### 校验与统计（接入流水线）

1. `POST /api/pipeline/validate?level=1` 整库校验，返回合格/不合格数量、错误原因、重复编号、重复文本与结论；每轮结果保存 `reports/level1/api_validate_<时间戳>.json` 并写入数据库 run_records 表。
2. `POST /api/pipeline/stats?level=1` 字/语法覆盖率、缺口、达标状态与补题建议；每轮结果保存 `reports/level1/api_stats_<时间戳>.json` 并写入 run_records。

### 状态与发布

1. `POST /api/questions/{id}/status`，body `{"status": "..."}`。流转规则：draft→{validated,rejected,ready}；validated→{ready,rejected,draft}；rejected→{draft}；ready→{rejected}；published→{rejected}。非法流转返回 400。
2. `POST /api/questions/{id}/publish` 单题发布：发布前检查（题目校验通过 + 题库整体统计达标），不通过返回 400 并列出原因。
3. `POST /api/pipeline/publish`，body `{"level": 1}` 整级发布：先做整体达标检查，通过后把该等级全部 ready/validated/draft 题置为 published。防止未达标题库发布。

### 抽题

1. `GET /api/questions/random?level=1&n=1` 按等级抽题：仅 published 题中等概率抽取，n 上限 20；抽中后更新 last_selected_at。
2. `GET /api/questions/recommend?level=1&n=1&C=10&candidate_size=20&recent_minutes=10` 按历史覆盖程度抽题（见下节）。
3. `POST /api/questions/{id}/recorded` 学生端保存一条有效录音后调用，rec_count +1。覆盖口径：rec_count 只统计成功上传并保存的有效录音；同一学生重录是否计入须与学生端书面统一。

### 错误处理约定

1. 不存在的题目：404 + `{"detail": "..."}`。
2. 参数错误（非法 status、n 超范围、非法状态流转）：400 / 422 + 明确中文原因。
3. 空题库或无 published 题抽题：404 + 说明（先导入 / 先发布）。
4. 发布不通过：400 + 逐条未达标原因。

## 4. 按覆盖程度抽题算法（权重已更新）

两阶段抽取：

1. 候选集：该等级 published 题中 `rec_count` 最低的前 `candidate_size`（默认 20）题。
2. 排除最近 `recent_minutes`（默认 10 分钟）内抽过的题后，按权重加权不放回随机抽取 n 题：

```text
w = max(0, C - rec_count)     C 默认 10，可通过 ?C= 调整
```

- `w = 0` 的题（录音数已达 C）不参与抽取；候选全为 0 时返回 404。
- 短时间防重复：last_selected_at 在时间窗内的题先排除；若候选被排空，时间窗自动减半放宽，并在返回 `algorithm.window_relaxed_min` 中注明。
- 返回体含 `algorithm` 段：公式、C、候选集大小、时间窗及本次实际使用的权重，便于验收核对。

> 变更说明：分工计划原权重 `w = 1 / (1 + rec_count)` 已按要求改为 `w = max(0, C - rec_count)`（线性衰减，超过 C 次后不再抽取）。计划文档已同步更新。

3. 目前仅一级（level=1）有题库；新增等级需提供 `data/levels/levelN.json` 与对应题库文件后复用同一套流程。
