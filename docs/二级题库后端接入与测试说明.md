# 二级题库后端接入与测试说明

## 1. 当前状态

项目后端只会从 SQLite 数据库中抽取 `published` 状态的题目。把 JSON 文件上传到 GitHub 后，题目不会自动进入数据库，也不会自动发布。

当前仓库中的 `backend/bank.db` 只有一级题目。资料包中的 `二级题库.json` 目前是空题库，不能直接导入二级题目。正式接入前，必须准备一个包含真实题目的二级题库 JSON 文件。

## 2. 后端需要的文件

提交或同步以下文件：

```text
data/levels/level1.json
data/levels/level2.json
scripts/lib.py
backend/import_bank.py
backend/main.py
backend/db.py
```

二级题库文件应放在后端默认路径：

```text
banks/level2/final.json
```

题库文件可以是纯数组，也可以是带 `items` 的对象：

```json
{
  "items": [
    {
      "id": "L2-001",
      "level": 2,
      "round": 1,
      "text": "题目正文。",
      "pinyin": "tí mù zhèng wén。",
      "grammar": ["G2-01"]
    }
  ]
}
```

每题至少需要 `id`、`level`、`text`、`pinyin`、`grammar`。导入脚本会把 `pinyin` 转换为后端统一的 `tokens` 字段。

## 3. 导入前检查

在项目根目录执行：

```powershell
python -m json.tool banks/level2/final.json > $null
python scripts/validate.py --level 2 --bank banks/level2/final.json --tag before_import
```

校验必须满足：

- 题目等级为二级；
- 文本只使用官方累计 600 字范围内的汉字；
- 句长符合二级配置；
- 语法编号属于二级语法点清单；
- 编号不重复；
- 文本不重复；
- 拼音与汉字逐字对应；
- 不含阿拉伯数字和拉丁字母。

如果校验失败，先修题库，不能直接发布。

## 4. 导入数据库

首次使用或需要保留现有数据库时，直接执行：

```powershell
python backend/import_bank.py --bank banks/level2/final.json --level 2
```

如果需要覆盖同编号的旧题目并重置运行字段，再使用：

```powershell
python backend/import_bank.py --bank banks/level2/final.json --level 2 --force
```

导入后检查数据库中的等级和状态：

```powershell
python -c "import sqlite3; c=sqlite3.connect('backend/bank.db'); print(c.execute(\"select level,status,count(*) from questions group by level,status order by level,status\").fetchall())"
```

新导入题目的初始状态是 `ready`，不是 `published`。因此此时还不能抽题。

## 5. 启动后端

```powershell
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8001
```

打开 Swagger：

```text
http://127.0.0.1:8001/docs
```

## 6. 接入后的测试顺序

### 6.1 查询等级题库

```powershell
curl.exe "http://127.0.0.1:8001/api/questions?level=2"
```

应返回二级题目，且每题的 `level` 都是 `2`。如果返回：

```json
{"total":0,"items":[],"detail":"该等级题库尚未完成"}
```

说明二级题目还没有成功导入数据库。

### 6.2 执行接口校验

```powershell
curl.exe -X POST "http://127.0.0.1:8001/api/pipeline/validate?level=2"
```

只有 `verdict` 为 `pass`、`invalid` 为 `0` 时才可以进入发布流程。结果会保存到：

```text
reports/level2/api_validate_*.json
```

### 6.3 执行统计

```powershell
curl.exe -X POST "http://127.0.0.1:8001/api/pipeline/stats?level=2"
```

需要确认字覆盖率、字频和语法点频次全部达到配置阈值。结果会保存到：

```text
reports/level2/api_stats_*.json
```

### 6.4 发布二级题库

校验和统计都通过后：

```powershell
curl.exe -X POST "http://127.0.0.1:8001/api/pipeline/publish" `
  -H "Content-Type: application/json" `
  -d '{"level":2}'
```

发布成功后，数据库中的二级题目状态会变为 `published`。如果发布返回 400，按返回的字表、统计或人工复核原因修复后再试。

## 7. 抽题测试

### 随机抽题

```powershell
curl.exe "http://127.0.0.1:8001/api/questions/random?level=2&n=3"
```

成功条件：返回 `level: 2`，返回题目数量不超过 3，所有题目状态为 `published`。

### 按录音覆盖推荐抽题

```powershell
curl.exe "http://127.0.0.1:8001/api/questions/recommend?level=2&n=3&C=10&candidate_size=20&recent_minutes=10"
```

推荐接口使用：

```text
w = max(0, C - rec_count)
```

录音次数较少的题目权重更高。首次导入时 `rec_count` 为 0，因此新题会优先被推荐。

### 录音计数测试

```powershell
curl.exe -X POST "http://127.0.0.1:8001/api/questions/L2-001/recorded" `
  -H "Content-Type: application/json" `
  -d '{"recording_id":"test-recording-001","speaker_id":"test-speaker"}'
```

同一个 `recording_id` 重复提交时，不应重复增加 `rec_count`。

## 8. 一键测试命令

启动服务后，在另一个终端执行：

```powershell
python backend/test_api.py --base http://127.0.0.1:8001
```

现有测试脚本主要覆盖一级固定数量，接入二级后还应人工确认以下二级专属结果：

```powershell
curl.exe "http://127.0.0.1:8001/api/questions?level=2"
curl.exe "http://127.0.0.1:8001/api/questions/random?level=2&n=1"
curl.exe "http://127.0.0.1:8001/api/questions/recommend?level=2&n=1"
```

## 9. 当前二级资料包的限制

当前资料包中的 `二级题库.json` 的 `items` 为空。因此它只能提供：

- 官方一级 300 字表；
- 官方二级新增 300 字表；
- 二级累计 600 字口径；
- 二级新增 81 个语法点及示例。

它不能直接提供可导入的二级题目。若暂时使用仓库中的 `banks/final2.json` 作为草稿题库，按官方 600 字表校验后仍有 63 道题含范围外汉字，不能直接发布。必须补充正式二级题目，或逐题修改、剔除这 63 道题后再执行导入和发布。

## 10. 最终验收条件

二级题库满足以下条件，后端才算接入完成：

1. `GET /api/questions?level=2` 返回正式题目；
2. 二级校验 `invalid=0`；
3. 二级统计 `verdict=pass`；
4. `/api/pipeline/publish` 返回发布数量；
5. `random?level=2` 能返回二级题目；
6. `recommend?level=2` 能返回二级题目；
7. 返回的每道题都带有逐字 `tokens` 和语法编号；
8. 录音计数后，推荐权重和覆盖记录正确变化。
